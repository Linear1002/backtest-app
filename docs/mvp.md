# MVP仕様

このドキュメントはMVPの範囲・戦略・指標の定義の正とする。
実装(Pythonリファレンス・C++・CUDA)とテストは、ここに書かれた定義に従う。

## 1. 目的と範囲

**ゴール**:東証上場の1銘柄に対して、移動平均クロス戦略のバックテストを画面から実行し、損益グラフと成績表を確認できること。

**MVPに入れないもの**

- 複数銘柄の同時実行
- GPU版(CUDA)。MVPはCPUで計算する
- ログイン・認証
- 課金
- 公開デプロイ(ローカル環境でのみ動かす。理由は「3. データ」の利用規約を参照)

## 2. 戦略:移動平均クロス

### 2.1 移動平均

- 終値の単純移動平均(SMA)を使う。
- 短期線 `SMA_short(t)` = 時点 t を含む直近 `short_window` 営業日の終値の平均。長期線 `SMA_long(t)` も同様に `long_window` で計算する。
- 移動平均の計算には、ユーザーが指定した期間内のデータだけを使う。
- 長期線を計算できない期間(期間開始から `long_window` 営業日未満)と、前日の移動平均がない日は、シグナルを出さない。

### 2.2 クロスの判定

当日 t と前日 t-1 の値を比べる。

| シグナル | 条件 |
|---|---|
| 上抜け(買い) | `SMA_short(t-1) ≤ SMA_long(t-1)` かつ `SMA_short(t) > SMA_long(t)` |
| 下抜け(売り) | `SMA_short(t-1) ≥ SMA_long(t-1)` かつ `SMA_short(t) < SMA_long(t)` |

- 当日の短期線と長期線が同じ値のときは、クロスとみなさない。
- 判定に使うのは時点 t までの終値だけで、t より後のデータは使わない(先読みバイアスの禁止)。

### 2.3 売買ルール

- **買いのみ(ロングオンリー)**。空売りはしない。
- 持っている株がないときに上抜けが出たら、買う。
- 持っている株があるときに下抜けが出たら、全株を売ってノーポジションにする。
- それ以外のシグナル(持ち株があるときの上抜け、持ち株がないときの下抜け)は無視する。

### 2.4 約定

- **当日の終値でシグナルを判定し、翌営業日の始値で約定する。**
- 期間の最終日に出たシグナルは、翌営業日がないので約定しない。
- 約定価格(スリッページ込み)
  - 買い:`fill_price = open(t+1) × (1 + slippage_rate)`
  - 売り:`fill_price = open(t+1) × (1 − slippage_rate)`
- 約定代金:`notional = fill_price × shares`
- 手数料:`fee = notional × fee_rate`(約定ごと。最低手数料は設けない)
- 買いのときは `notional + fee` を現金から引き、売りのときは `notional − fee` を現金に足す。

### 2.5 株数の決め方

- 手持ちの現金で買える最大の株数を、売買単位(東証は100株)の倍数で買う。
- `shares = floor(cash / (fill_price × (1 + fee_rate)) / lot_size) × lot_size`
- `shares` が0(100株分の資金に足りない)のときは買わずにスキップし、「資金不足で約定しなかった回数」に1を足す。スキップした後も、ノーポジションのまま次のシグナルを待つ。

### 2.6 期間の最後に持っている株

- 最終日の終値で評価額を計算するだけで、売却はしない。
- この未決済の取引は、取引回数と勝率に含めない。

## 3. データ

### 3.1 データソース(MVP):J-Quants API Free

| 項目 | 内容 |
|---|---|
| 対象 | 東証上場株・日足 |
| 期間 | 約2年分 |
| 遅延 | 12週間 |
| API | V2(`https://api.jquants.com/v2/equities/bars/daily`)、APIキーを `x-api-key` ヘッダーで渡す |
| 利用規約 | **私的使用のみ** |

**要確認**(実装前に公式ドキュメント https://jpx-jquants.com/ で確認する)

- V2レスポンスでの調整済み始値・終値と調整係数のフィールド名(V1では `AdjustmentClose` などだった)
- 銘柄コードの形式(4桁か5桁か)と、内部の銘柄ID(`TSE:7203`)との変換規則
- Freeプランで取れる正確な期間と、リクエスト数の制限

### 3.2 利用規約から来る制約

- 取得したデータは `data/` に保存し、Gitで管理しない(`.gitignore` 済み)。
- データをリポジトリやアプリ経由で配布しない。公開デプロイしないのはこのため。
- 将来サブスク化するときは、商用利用と再配布が許されるデータソースに切り替える必要がある。

### 3.3 データソースを差し替えられる設計

データ取得はインターフェース(データソース)の裏に隠し、バックテストの計算部分はJ-Quantsを直接知らないようにする。データソースの責務は次の3つ。

1. 銘柄一覧を返す(銘柄ID、銘柄名、市場)
2. 銘柄IDと期間を受け取り、調整済みの日足(日付・始値・高値・安値・終値・出来高)を返す
3. 取得できるデータの範囲(最初の日と最後の日)を返す

- 銘柄は「市場+コード」で一意に識別する(例:`TSE:7203`)。J-Quants固有のコード形式への変換は、データソースの中で行う。
- 取得したデータは共通の形式でParquetに保存し、計算エンジンにはこの共通形式だけを渡す。

### 3.4 市場ごとの設定(MVPは東証のみ)

| 項目 | 東証(TSE) |
|---|---|
| 通貨 | JPY |
| 売買単位 | 100株 |
| 取引カレンダー | データに存在する日を営業日とする |
| 値幅制限 | MVPでは扱わない(「7. 既知の簡略化」を参照) |

### 3.5 株式分割・配当

- 分割・併合を反映した**調整済み株価**を使う。
- 配当はMVPでは含めない。リターンは値動きだけで計算する。

### 3.6 上場廃止銘柄

- MVPの銘柄リストには、現時点で上場している銘柄だけを載せる。
- そのため、期間中に上場廃止になった銘柄は選べない。これは生存者バイアスの原因になる。MVPは1銘柄ずつ実行するので影響は限られるが、結果画面や仕様書でこの点を隠さない。

## 4. 画面の流れ

```
銘柄選択 → 戦略選択 → 詳細設定 → 実行 → 結果
```

| 画面 | 内容 |
|---|---|
| 銘柄選択 | 東証の銘柄を、コードまたは銘柄名で検索して1つ選ぶ |
| 戦略選択 | MVPでは「移動平均クロス」だけ |
| 詳細設定 | 期間(開始日・終了日)、短期日数、長期日数、手数料率(%)、スリッページ率(%)、初期資金(円) |
| 実行 | 入力チェックをしてから計算を始める |
| 結果 | 損益グラフ(日々の資産額)、成績表、資金不足で約定しなかった回数 |

### 4.1 詳細設定のデフォルト値

| 項目 | デフォルト |
|---|---|
| 短期日数 | 5 |
| 長期日数 | 25 |
| 手数料率 | 0.1% |
| スリッページ率 | 0.05% |
| 初期資金 | 1,000,000円 |
| 期間 | 取得できるデータの全範囲 |

手数料率とスリッページ率は0にしない(0を入力すること自体は許す)。

### 4.2 入力チェック

エラーのときは実行せず、日本語のメッセージを表示する。

| 条件 | エラーメッセージ(例) |
|---|---|
| 短期日数 ≥ 長期日数 | 「短期の日数は長期の日数より小さくしてください」 |
| 日数が1未満、または整数でない | 「日数は1以上の整数で入力してください」 |
| 期間がデータの範囲外 | 「指定した期間のデータがありません(取得可能:YYYY-MM-DD〜YYYY-MM-DD)」 |
| 開始日 > 終了日 | 「開始日は終了日より前の日付にしてください」 |
| 手数料率・スリッページ率が負 | 「手数料率とスリッページ率は0以上で入力してください」 |
| 初期資金が0以下 | 「初期資金は1円以上で入力してください」 |

## 5. 成績表の指標

日ごとの資産額を `equity(t) = cash(t) + shares(t) × close(t)` とする(t は期間内の営業日、t = 0 が開始日)。開始日の資産額は初期資金。

日次リターンは `r(t) = equity(t) / equity(t-1) − 1`(t = 1 … N)。N は日次リターンの数(期間内の営業日数 − 1)。

| 指標 | 定義 |
|---|---|
| 総リターン | `equity(N) / 初期資金 − 1` |
| 年率リターン | `(equity(N) / 初期資金)^(245 / N) − 1` |
| 最大ドローダウン | `max over t of (1 − equity(t) / max_{s≤t} equity(s))`。正の割合で表示する(例:12.3%) |
| シャープレシオ | `mean(r) / std(r) × √245`。無リスク金利は0、`std` は標本標準偏差(ddof=1)。`std(r) = 0` のときは「算出不可」と表示する |
| 勝率 | 決済した取引(買い→売りの1往復)のうち、損益がプラスだったものの割合。損益は手数料・スリッページを引いた後で判定する。損益0は負けに数える。決済した取引が0回のときは「−」と表示する |
| 取引回数 | 決済した取引(往復)の回数 |

1往復の損益:`(売りの notional − 売りの fee) − (買いの notional + 買いの fee)`

年間営業日数は245日とする。

## 6. 正しさの前提(まとめ)

- 先読みバイアス:シグナルは当日終値で判定し、約定は翌営業日の始値。移動平均の計算に、時点 t より後のデータを使わない。
- 手数料・スリッページ:必ずパラメータとして持ち、デフォルトは0にしない。
- 株式分割:調整済み株価を使う。配当は含めない。
- 生存者バイアス:上場廃止銘柄は対象外。そのことを明記する。
- 実装の正しさは、Pythonリファレンス実装 → C++ CPU版 の順に一致テストで確認する(CUDA版はMVPに入れない)。

## 7. 既知の簡略化

MVPでは次のことを扱わない。結果は現実の売買と違うことがある。

- **ストップ高・ストップ安**:実際には約定できない日でも、始値で約定したものとして計算する。
- **売買単位と調整済み株価のずれ**:調整済み株価で100株単位の株数を計算するので、分割前の期間では、実際に買えた株数や必要な資金とずれる。
- **配当**:含めない。
- **最低手数料・税金**:扱わない。
- **上場廃止銘柄**:対象外(「3.6 上場廃止銘柄」を参照)。
