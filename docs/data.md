# 株価データの使い方

仕様は `docs/mvp.md` の3章。ここでは「実際にどう使うか」をまとめる。

## 2種類のデータソース

| 市場(銘柄IDの前半) | データソース | APIキー | 公開デモに使えるか |
|---|---|---|---|
| `DEMO:` | 架空データ(`backend/marketdata/synthetic.py`) | 不要 | 使える |
| `TSE:` | J-Quants API(`backend/marketdata/jquants.py`) | 必要 | **使えない**(私的使用のみ) |

APIキーがなくても、`DEMO:` の架空銘柄でアプリ全体を動かせる。架空データは決まった乱数の種から作るので、毎回同じ値になる。

## J-Quants を使う準備

1. [J-Quants](https://jpx-jquants.com/) に登録して、ダッシュボードの **[API Keys]** 画面でAPIキーを発行する
2. リポジトリ直下で `.env.example` をコピーして `.env` を作り、`JQUANTS_API_KEY=` の後ろにキーを書く
   ```bash
   cp .env.example .env
   code .env   # VS Code で開いて書く
   ```
3. `git status` で `.env` が表示されないことを確かめる(Git に無視されている)

APIキーは Claude Code にもチャットにも貼らない。プログラムもキーを画面やログに出さない(`CLAUDE.md`「秘密情報」)。

## コマンド

| コマンド | 内容 |
|---|---|
| `make data-symbols` | 東証の銘柄一覧(普通株)を取得して保存する。最初に1回。数分かかることがある |
| `make data-fetch SYMBOLS="TSE:7203 TSE:6758"` | 日足を取得して保存する |
| `make data-info SYMBOL=TSE:7203` | 保存済みデータの期間・売買不成立の日・権利落ちを表示する(`DEMO:` も可) |

画面やAPIから東証の銘柄を選んだときも、保存されていなければその場で取得する(1銘柄につき1〜2回のリクエスト)。
ただし銘柄一覧は時間がかかるので、画面からは取りにいかない。先に `make data-symbols` を実行しておく。

## 保存の仕組み

- 保存先:`data/jquants/`(Git 管理外)
  - `symbols.parquet`:銘柄一覧
  - `bars/TSE_7203.parquet`:銘柄ごとの日足
- 保存する値:未調整の四本値・出来高・売買代金・調整係数(`AdjFactor`)・権利落ちの種類(`ExRT`)・ストップ高/安の到達フラグ
- 保存しない値:調整済み株価(`AdjC` など)。新しい分割があると過去の値までさかのぼって書き換わり、時点 t で知り得た値にならないため(`docs/mvp.md` 2.2)
- 取得日時は Parquet ファイル自身のメタデータに書く(UTC。画面には日本時間で出す)
- 取得から7日たったデータは、次に使うときに全期間を取り直す(`.env` の `JQUANTS_MAX_AGE_DAYS` で変更可)
- 取り直したデータは、保存済みのデータに**合わせて**保存する
  - 同じ日付は新しい値にする(J-Quants 側で過去のデータが訂正されたとき(`docs/mvp.md` 3.1)も、取り直しで反映される)
  - 新しく取れなかった古い日付は残す。Free プランは「直近の約2年」なので、取れる期間は日がたつと後ろへずれる。
    取り直すたびに古い日付が消えると、前と同じ条件のバックテストを後から再現できなくなるため
  - ただし、取れる期間から外れた日付に訂正があっても、反映はできない
- 取り直しに失敗したとき(回数の上限・ネットワーク・J-Quants の障害など)は、保存済みのデータで計算を続け、
  結果画面に「最新のデータを取得できなかったため、◯◯に取得したデータで計算しました」と出す
- APIキーがないときは、保存済みのデータだけを読む(古くても取り直さない)
- `make data-info` は保存済みのデータを表示するだけで、取り直さない
- 保存の形式(列や `schema_version`)が変わった古いファイルは、保存されていないものとして取り直す
- 銘柄一覧(`make data-symbols`)を取得してあれば、一覧にない銘柄(上場廃止など)は画面・API から実行できない。
  MVP は「現在上場している銘柄」だけを対象にしているため(`docs/mvp.md` 3.6)。一覧を取得していないときは確かめない

## リクエスト数の上限

Free プランは1分間に5回まで(アカウント単位)。クライアントは直近60秒の回数を数えて、上限に達したら待つ。
`429` が返ったときは、2分のあいだ誰も送らないようにしてから再送する(J-Quants は `Retry-After` ヘッダーを返さない。
公式の推奨は「1分以上(ウィンドウがスライドするため、確実を期す場合は2分程度)待機」。早く再送すると、その `429` も回数に数えられる)。

- **コマンド**(`make data-fetch` など):必要なだけ自動で待つ
- **画面・API**:15秒より長く待つ必要があるときは、待たずに「約◯秒後に、もう一度試してください」と返す(画面を何分も止めないため)。
  待ち時間が90秒以上なら「約◯分」と書く(`429` のあとは「約2分待ってから、もう一度試してください」)
- 回数の数え方は、API サーバーの中ではリクエストの間で共有している。ただし**プロセスごと**に数えるので、
  API サーバーを動かしたまま `make data-check`(約10分)などのコマンドを実行すると、合わせて上限を超えることがある。
  その場合は `429` を受けて待つので壊れはしないが、時間がかかる。コマンドを使うときは API サーバーを止めておくとよい

有料プランに変えたら、`.env` の `JQUANTS_REQUESTS_PER_MINUTE` を変える(Light は60)。

## 利用規約について(必ず守る)

J-Quants のデータは、利用規約により**登録したユーザー本人の私的使用**に限られる。

- `data/` のファイルを Git にコミットしない・人に渡さない
- J-Quants のデータを表示するアプリをインターネットに公開しない
- ポートフォリオとして見せるときは、`DEMO:` の架空データを使う(スクリーンショット・デモ動画・公開デモ)
- サブスク化するときは、商用利用と再配布が許されるデータソースと契約し、`DataSource` を満たすクラスを追加する
- **利用契約が終わったら、`data/jquants/` を消す**(利用規約7条:解約したらデータと複製物をすべて消す)。
  Free プランは登録から1年で自動的に終わるので、その時期に注意する。再登録したら `make data-fetch` で取り直す

(これは利用規約を読んだ範囲での整理で、法律の助言ではない。商用化の前に改めて確認すること)
