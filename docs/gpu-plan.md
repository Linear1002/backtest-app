# GPU 版の計画(MVP のあと)

MVP(1銘柄・1組のパラメータ)が C++ 版まで一致したら、次は **パラメータの総当たり(スイープ)を CUDA で並列にする**。
これがこのアプリの「強み」(CLAUDE.md:GPU で大量・高速に計算できる)の本体になる。

GPU のコード(`engine/cuda/`)は開発者が自分で書く(CLAUDE.md の役割分担)。

**いまの状態**:総当たりの仕様(`docs/sweep.md`)、Python の総当たり(正解。`engine/reference/sweep.py`)と正解データ
(`tests/golden/sweeps/`)、API(`POST /api/sweeps`)とヒートマップの画面はできている(下の G1・G7)。
いまは Python を複数のプロセスで動かして計算している。C++ 版・CUDA 版の総当たりを書いたら、そこに差し込む。

## 1. 何を作るか

**1銘柄・1つの期間で、短期日数 × 長期日数の組み合わせをすべてバックテストし、成績を表(とヒートマップ)にする。**

```
短期 2〜50日 × 長期 10〜200日(短期 < 長期)= 8,498 通り
```

- 1つ1つの組み合わせの計算は MVP とまったく同じ(`docs/mvp.md` の 2章・5章)
- 結果は組み合わせごとの成績指標(総リターン・最大ドローダウン・シャープレシオ・取引回数など)
- 画面:ヒートマップ(横=短期、縦=長期、色=シャープレシオなど)。マスを押すと、その組み合わせの通常の結果画面を開く

### いまの速さ(出発点)

Python リファレンス実装で、架空銘柄 DEMO:1001 の全期間(1,119営業日)を1回バックテストすると **16〜85ミリ秒**
(長期日数が長いほど遅い。移動平均の和を、日ごとに長期日数の分だけ足し直すため)。
8,498 通りを1つのプロセスで順番に回すと **約7分**(213通りを抜き出して測った平均 48 ミリ秒からの見積もり。
このリポジトリを作ったクラウド環境での目安なので、自分の PC で測り直すこと)。
画面で待つには長すぎるので、いまの API は Python の上限を 2,000通りにして、CPU のコアの数のプロセスで並列に計算している。
C++ 版(1スレッド)で何倍、複数スレッドで何倍、GPU で何倍になるかを測って比べるのが、この段階のゴール。

## 2. 正しさをどう保つか(最初に決めること)

GPU 版も「Python リファレンス → C++ CPU 版 → CUDA 版」の順に一致させる(CLAUDE.md の正しさの基準)。

### 2.1 一致の基準

| 項目 | 基準 | 理由 |
|---|---|---|
| シグナルの日付・約定日・株数・取引回数 | **完全に一致** | MVP と同じ。1日ずれると、その後の売買が全部変わる |
| 資産額・成績指標 | `|GPU − CPU| ≤ 1e-12 + 1e-9 × |CPU|` | MVP と同じ |

### 2.2 浮動小数点を CPU とそろえるための決まり

- **FMA を止める**:nvcc は標準で掛け算と足し算を1つの命令(FMA)にまとめる。`--fmad=false` を付ける(C++ 側の `-ffp-contract=off` と同じ目的)
- **足す順番を変えない**:移動平均の和は、CPU と同じく古い日から新しい日の順に1つずつ足す。GPU でよく使う「木の形に足す(リダクション)」や「累積和で引き算する」は、丸め誤差が変わるので、**一致させる段階では使わない**
- **`--use_fast_math` は使わない**(割り算・平方根の精度が落ちる)
- `pow` などの数学関数は、CUDA と CPU(glibc)で最後の1〜2桁がずれることがある。成績指標は許容誤差で比べるので問題ないが、**シグナルの判定(D(t) の符号)には使わない**(いまの仕様でも使っていない)

### 2.3 速くするときの選択肢(一致させたあと)

累積和(prefix sum)を使うと移動平均が1日あたり O(1) で計算できるが、足す順番が変わるので、`D(t) = 0` 付近でシグナルが入れ替わることがある(`docs/mvp.md` 8章)。使うなら、先に次を決める:

- 「ほぼ同値」の日(`|D(t)|` がとても小さい日)だけはシグナルの違いを許し、その日数を報告する
- または、GPU は「候補をしぼる」だけに使い、上位の組み合わせを CPU の倍精度で計算し直して表示する(2段階方式。4章)

## 3. 並列にする方法(案)

### 3.1 計算を2つに分ける

1. **移動平均の和の表を作る**:日数 w(2〜200)と有効日 t ごとに S_w(t) を計算して、表(w × 日数)にする
   - 1つの (w, t) を GPU の1スレッドが担当する。計算は `engine/reference/indicators.py` と同じ:t から過去へ CumAdj を掛け、古い日から順に足す
   - 同じ (w, t) の値は、どの組み合わせから見ても同じ。**組み合わせごとに移動平均を計算し直さなくてよくなる**(ここがいちばん効く)
   - 大きさの目安:200 × 1,200日 × 8バイト ≒ 2MB。RTX 3060 の 12GB に余裕で入る
2. **組み合わせごとに売買をたどる**:1つの (短期, 長期) を1スレッドが担当し、1日目から順に 2.5 の手順1〜4を行う
   - D(t) は表から `S_short(t) × long − S_long(t) × short` で作る
   - 状態(現金・株数・約定待ちの注文・持っている取引)はスレッドごとのローカル変数
   - 出力は組み合わせごとの成績指標。シャープレシオは「平均 → 偏差の2乗の和」の2回の計算が必要なので、日々の資産額を一時的に保存するか、2回たどる(8,498 × 1,200 × 8バイト ≒ 82MB)

### 3.2 気をつけること

- **分岐の違い(ダイバージェンス)**:組み合わせごとに売買する日が違うので、同じワープの中で処理が分かれる。まずは気にせず書き、測ってから考える
- **メモリの読み方(コアレッシング)**:表を「日 × w」と「w × 日」のどちらの並びで置くかで速さが変わる。両方試して測る(行列積のタイル化で使った考え方が役に立つ)
- **転送時間**:CPU → GPU のデータ転送は、計算時間とは別に測って報告する

### 3.3 RTX 3060 で知っておくこと(正直な注意)

- RTX 3060(Ampere、Compute Capability 8.6)は、**倍精度(double)の計算速度が単精度(float)の 1/64** しかない(ゲーム向けの GPU は倍精度を削っている)
- この計画は「CPU と一致させる」ために倍精度を使うので、単精度の行列積のような速さは出ない
- それでも、8,498 通りを同時に計算できるので、1スレッドの CPU よりは大きく速くなるはず。**どれだけ速くなるかは測って確かめる**(予想で書かない)
- 面接で話せるポイント:「倍精度が遅い GPU で、正しさと速さをどう両立したか」(2段階方式など)

## 4. 過剰最適化(カーブフィッティング)への備え

8,498 通りを試して一番良いものを選ぶと、**偶然うまくいった組み合わせを選んでしまう**(データスヌーピング)。
「数字を正直に見せる」というこのアプリの方針(`frontend/DESIGN.md`)に合わせて、次を必ず入れる。

- **試した数を表示する**:「8,498 通りの中で最も良い組み合わせ」と書く。1通りだけ試した結果とは意味が違う
- **期間を分ける(アウトオブサンプル)**:前半で選んだ組み合わせを、後半(選ぶのに使っていない期間)で試した結果も並べる
- **ウォークフォワード**:「過去 N 年で選ぶ → 次の1年で試す」を少しずつずらして繰り返す
- **ヒートマップで「山」の形を見る**:良い組み合わせの周りも良い(なだらかな山)なら、たまたまではない可能性が高い。1マスだけ飛び抜けているなら疑う
- 発展:Deflated Sharpe Ratio(Bailey & López de Prado, 2014)、Probability of Backtest Overfitting(Bailey ほか)。試した数を考えに入れてシャープレシオを割り引く考え方

- **C++ の複数スレッド版と比べる**(1スレッドの Python と比べて「1000倍速い」と言っても、面接では評価されない)
- GPU の初回起動の時間(ウォームアップ)を除いてから測る。転送時間は別に書く
- 同じデータ・同じ格子・同じオプション(手数料など)で比べる

## 6. API と画面(できた。Claude が書いた部分)

仕様は `docs/sweep.md`(10章が API)。計画のときの案から、次のように決めた。

- 計算に時間がかかるので、**ジョブ**にした:`POST /api/sweeps` はすぐに返り、画面は `GET /api/sweeps/{id}` で途中経過を問い合わせる。`DELETE` で中止できる
- 選ぶ期間・検証期間(`holdout_start_date`)の成績を、組み合わせごとに返す。順位・順位相関・1位のとなりの平均は API が計算する(`backend/sweep_summary.py`)
- 組み合わせの数の上限:Python は 2,000通り、C++・CUDA は 20,000通り(できたら)
- 画面:条件の画面で「総当たりで比べる」を選ぶ → ヒートマップ(選ぶ期間 / 検証期間で切り替え)・まとめ・上位の表。マスを選ぶと、その組み合わせを通常のバックテストで詳しく見られる

C++ 版・CUDA 版の総当たりをつなぐときは、`backend/sweeps.py` の `run_pairs` の代わりに呼ぶ関数を足す
(入力と出力の形は `engine/reference/sweep.py` の `run_pairs` と同じにする)。
