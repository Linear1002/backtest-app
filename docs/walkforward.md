# ウォークフォワード分析の仕様

このドキュメントは、ウォークフォワード分析の正とする。
1つの組み合わせの計算は `docs/mvp.md`、組み合わせの作り方と並べ方は `docs/sweep.md`、比べる相手(買い持ち)は `docs/benchmark.md` と同じで、
ここでは「区切り方」「選び方」「つなぎ方」だけを決める。

## 1. 目的と範囲

総当たり(`docs/sweep.md`)の「選ぶ期間 → 検証期間」は、選んで確かめるのが1回だけ。
実際に売買ルールを使うなら、**一定の間隔で、直近のデータで日数を選び直す**ことになる。ウォークフォワード分析は、それを過去のデータでそのまま再現する。

```
├── 選ぶ期間(2年)──┤ 使う期間(半年)
     ├── 選ぶ期間(2年)──┤ 使う期間(半年)
          ├── 選ぶ期間(2年)──┤ 使う期間(半年)
```

- 区切りごとに、**直前の選ぶ期間だけ**で総当たりの1位を選び、**その次の使う期間だけ**、その日数で売買する
- 使う期間をつなげた成績が、「総当たりで1位を選ぶ」という**選び方そのもの**の成績になる。どの使う期間も、選ぶのに使っていない期間
- 比べる相手:同じ期間(使う期間をつなげた期間)の買い持ち
- 総当たりと同じく、1銘柄・移動平均の日数(短期・長期)だけを選ぶ。計算エンジンは Python リファレンス実装

## 2. 入力

| 入力 | 内容 |
|---|---|
| `start` `end` | 期間(`docs/mvp.md` と同じ) |
| 格子 | `docs/sweep.md` 2章と同じ(短期・長期の最小・最大・刻み) |
| `objective` | 1位を選ぶ基準。**シャープレシオ**(既定)か**総リターン**。最大ドローダウンは選べない(一度も売買しない組み合わせが最大ドローダウン0で1位になり、「何もしない」を選ぶことになるため) |
| `in_sample_months` | 選ぶ期間の長さ(か月)。1〜120 の整数。画面では 1年・2年(既定)・3年・5年 から選ぶ |
| `out_of_sample_months` | 使う期間の長さ(か月)。1〜60 の整数。画面では 3か月・6か月(既定)・1年 から選ぶ |
| 費用 | 手数料率・スリッページ率・初期資金(`docs/mvp.md` 4.2・4.3) |

## 3. 区切り方

- 月を足す:`add_months(d, m)` は、`d` の年月に `m` か月を足し、日は `d` の日にする。その月にその日がなければ、その月の末日にする
  (例:1月31日 + 1か月 = 2月28日。うるう年は29日)
- 区切り `k`(`k = 1, 2, …`)の期間は、すべて `start` から月を足して決める(前の区切りから足し重ねない。月末の日がずれていかないように)。
  `I` は `in_sample_months`、`M` は `out_of_sample_months`
  - 選ぶ期間:`add_months(start, (k − 1) × M)` 〜 `add_months(start, I + (k − 1) × M)` の前日
  - 使う期間:`add_months(start, I + (k − 1) × M)` 〜 `add_months(start, I + k × M)` の前日
- **使う期間が `end` までに丸ごと入る区切りだけを作る**(使う期間の終わりの日 ≤ `end`)。最後の区切りの使う期間のあとに残った日は使わない(画面に書く)
- 区切りは暦(日付)だけで決まる。そのため、画面は株価のデータがなくても、区切りの数と日付を前もって出せる
- 隣の区切りとの関係:区切り `k` の使う期間の次の日から、区切り `k + 1` の使う期間が始まる(すき間も重なりもない)。選ぶ期間は前の区切りと重なる(ずらして使う)
- **選ぶ期間の始まりをそろえる**:区切りごとに、総当たりと同じ決まり(`docs/sweep.md` 3章)で、選ぶ期間の始まりを
  「それより前の有効日が、格子の中でいちばん長い長期日数 `L` 個そろう最初の営業日」まで遅らせる(足りていれば、そのまま)。
  ふつうは区切り1(データの初日から始めたとき)だけが遅れる。これで、どの区切りの選ぶ期間でも、すべての組み合わせを同じ日から評価する
- どの区切りも、そろえたあとの選ぶ期間と、使う期間の営業日が3日以上あること(`docs/mvp.md` 4.3)

## 4. 選び方

- 区切りごとに、その選ぶ期間で、格子のすべての組み合わせを計算する(`docs/sweep.md` 4章と同じ:組み合わせごとに1組のバックテスト。株を持たずに始め、ウォームアップは選ぶ期間より前のデータ)
- `objective` の値で並べ(`docs/sweep.md` 7章の並べ方)、**1位を選ぶ**
  - **同率1位**のときは、組み合わせの順番(短期の小さい順 → 長期の小さい順)で最初のものを選ぶ。ウォークフォワードは区切りごとに必ず1つに決める必要があるため。同率だった数は結果に出す
  - すべての組み合わせの値が算出不可(例:どの組み合わせも一度も売買せず、シャープレシオが出ない)なら、**選ばない**。その使う期間は売買せず、現金のままにする
- 選ぶときに使うのは、その区切りの選ぶ期間の成績だけ(使う期間の値・ほかの区切りの値は使わない)
- 選ぶ期間の計算の初期資金は、入力の初期資金(その時点の資産ではない)。どの区切りでも同じ条件で選ぶため

## 5. 使う期間の計算とつなぎ方

- 選んだ組み合わせで、使う期間を1組のバックテストとして計算する(`docs/mvp.md`。株を持たずに始め、ウォームアップは使う期間より前のデータ)
- **初期資金は、前の区切りの使う期間の最後の資産を、清算したあとの額**(区切り1は入力の初期資金)
- **区切りでの清算**:使う期間の最後に株を持っていたら、その最終日の評価価格(`docs/mvp.md` 5章)で、売りと同じ費用を引いて現金にしたものとする

```
清算したあとの額 = 現金 + 株数 × 評価価格 × (1 − スリッページ率) × (1 − 手数料率)
```

  - **区切りごとに、株を持たない状態から始める**(`docs/mvp.md` の1組のバックテストをそのまま使う)。移動平均クロスは、クロスが起きた日にしか買わないので、
    次の区切りで同じ日数を選び、短期線が長期線の上にあるままでも、**次にゴールデンクロスが起きるまで買わない**
  - そのため、実際に持ち続けた場合と比べて、上昇の続きを取り逃がすことも、下落を避けることもある。**良くも悪くもなりうる**(厳しめとは限らない)。
    清算で引く売りの費用だけは、実際より多め。そのかわり「清算コスト控除前」の甘さは区切りごとにはたまらない
  - 最後の区切りの最終日も同じ式で清算した額を出す(画面では、清算する前の額と並べる)
- **つないだ資産額の系列**:区切り1の使う期間の初日から、最後の区切りの使う期間の最終日まで、営業日ごとに1つ
  - その日が属する区切りの使う期間の資産額。区切りの最終日だけは、**清算したあとの額**(次の区切りの初日は、この額から始まる)
  - ただし、最後の区切りの最終日は清算する前の額(`docs/mvp.md` 2.9 と同じ。清算したあとの額は別に出す)
- **つないだ成績**:この系列で、`docs/mvp.md` 5章と同じ定義の総リターン・年率リターン・最大ドローダウン・シャープレシオを計算する(初期資金は入力の初期資金。日次リターンの数は系列の長さ − 1)
- 比べる相手:区切り1の使う期間の初日 〜 最後の区切りの使う期間の最終日 の、買い持ち(`docs/benchmark.md`。この期間全体で1回)

## 6. 出力

**区切りごと**

| 項目 | 内容 |
|---|---|
| 選ぶ期間・使う期間 | 開始日・終了日と、最初・最後の営業日、営業日の数 |
| 選んだ組み合わせ | 短期・長期の日数(選ばなかったときは なし) |
| 選ぶ期間の値 | 選んだ組み合わせの、選ぶ期間の `objective` の値 |
| 同率の数 | 1位と同じ値だった組み合わせの数(1なら同率なし) |
| 使う期間の成績 | 総リターン・最大ドローダウン・シャープレシオ・取引回数(選ばなかったときは、売買なしの成績) |
| 清算 | 使う期間の最後に株を持っていたか、清算する前・したあとの資産 |
| 使う期間の買い持ち | その使う期間だけの買い持ちの総リターン(区切りごとに比べるため)。元手は戦略と同じ、その区切りの初期資金(買えるかどうか・売買単位の切り捨てを戦略とそろえる) |

**全体**

- つないだ資産額の系列(日付・資産額・買い持ちの資産額)、つないだ成績、同じ期間の買い持ちの成績
- 区切りの数、使う期間で買い持ちの総リターンを上回った区切りの数(その使う期間で買い持ちを買えた区切りだけで数える)、選んだ組み合わせが前の区切りから変わった回数
- 試した組み合わせの数(格子の数)と、計算した回数(組み合わせの数 × 区切りの数 + 区切りの数)

## 7. チェックの順番

最初に見つかった誤りで止める。メッセージは画面と同じ文(`tests/fixtures/walkforward_messages.json`)。

1. 格子(`docs/sweep.md` 5章の1)
2. 費用(`docs/sweep.md` 5章の2)
3. `objective`・`in_sample_months`・`out_of_sample_months`
4. 期間:開始日 ≤ 終了日
5. 日付の順番(入力全体。`docs/mvp.md` 3.7)
6. 区切り:区切りが1つも作れない → 区切りの順に、そろえたあとの選ぶ期間・使う期間の営業日が3日未満
7. 計算の量:組み合わせの数 × 区切りの数 が上限を超える(9章)
8. データの異常:いちばん長い長期日数で「区切り1のそろえた選ぶ期間の始まり 〜 最後の使う期間の終わり」を読み込む範囲を、`docs/mvp.md` 3.7 で確かめる。
   この範囲は、すべての区切り・すべての組み合わせ・買い持ちの読み込む範囲を合わせたものに等しい
9. 計算の途中で気づく誤り(株数の桁あふれなど)。区切りの順 → 組み合わせの順で最初のもの

| 誤り | メッセージ |
|---|---|
| `objective` が使えない | 「1位を選ぶ基準は、シャープレシオか総リターンを選んでください」 |
| 選ぶ期間の長さ | 「選ぶ期間の長さは1〜120か月の整数で入力してください」 |
| 使う期間の長さ | 「使う期間の長さは1〜60か月の整数で入力してください」 |
| 区切りがない | 「期間が短すぎて、選ぶ期間(I か月)と使う期間(M か月)を1回も取れません。期間を広げるか、選ぶ期間・使う期間を短くしてください」 |
| そろえたあとの選ぶ期間が3営業日未満 | 「長期の日数(最長L日)のウォームアップに使う日を除くと、区切り k の選ぶ期間の営業日が3日未満になります。長期の日数を短くするか、選ぶ期間を長くしてください」 |
| 使う期間が3営業日未満 | 「区切り k の使う期間の営業日が3日未満です。使う期間を長くしてください」 |
| 計算が多すぎる | 「計算が多すぎます(N通り × 区切りK回 = X回)。このエンジンでは Y回までです。範囲を狭める・刻みを大きくする・使う期間を長くする、のどれかをしてください」 |

## 8. 画面に必ず出すこと

- **つないだ成績と、同じ期間の買い持ち**を並べる(いちばん上)
- 区切りごとの表:選んだ日数が区切りごとにどれくらい変わったか。**選ぶ日数が毎回大きく変わるなら、選び方が「その時々のたまたま」を追いかけている**可能性がある
- 選ぶ期間は区切りごとに重なっているが、**使う期間は重ならない**。つないだ成績は、どの日も「その日より前のデータだけで選んだ日数」で売買した結果
- 区切りごとに清算し、株を持たない状態から始めること(次のゴールデンクロスまで買わないので、実際に持ち続けた場合とは良くも悪くも違う)。最後の区切りのあとに残った日を使っていないこと
- 試した組み合わせの数。ウォークフォワードでも、格子・選ぶ期間の長さ・使う期間の長さを変えて何度も試すと、その選び方自体が過剰最適化になる
- `docs/mvp.md` の注意(生存者バイアス・配当なし・約定の前提)と、`docs/benchmark.md` 5章の注意

## 9. 上限

上限は、選ぶ期間の計算(組み合わせの数 × 区切りの数)で決める。エンジンごとに、**総当たりの組み合わせの上限の2倍**(総当たりの「選ぶ期間 + 検証期間」と同じ量)。
使う期間の計算(区切りの数だけ)は上限に数えない。

| エンジン | 組み合わせの数 × 区切りの数 |
|---|---|
| Python リファレンス実装 | 4,000回(総当たりの 2,000通り × 2) |
| ほかのエンジン(C++ 版・CUDA 版をつないだとき) | そのエンジンの総当たりの上限 × 2 |

## 10. API

```
POST   /api/walkforwards        始める → 202 と、ジョブの id
GET    /api/walkforwards/{id}   途中経過(終わった数 / 全体の数)。終わったら結果
DELETE /api/walkforwards/{id}   中止する
```

- 総当たりと同じジョブの仕組み(`docs/sweep.md` 10章)。同時に計算できるのは、総当たりと合わせて2つまで
- 途中経過の数は、組み合わせの数(1つの組み合わせを、すべての区切りの選ぶ期間で計算して1つ)
- 入力チェック(7章の1〜8)は `POST` で行い、誤りがあれば 422。9 はジョブの失敗として返す

## 11. 確かめ方

- 区切り方:月末・うるう年・最後に残る日・区切りが1つだけ・作れない、の表(`tests/fixtures/walkforward_windows.json` を Python と画面の両方のテストが読む)。
  そろえ方(区切り1の始まりが遅れる・売買不成立の日をまたぐ)
- 選び方:同率1位・すべて算出不可・選ぶ期間の値だけで選ぶこと(使う期間のデータを書き換えても、選ぶ組み合わせが変わらない)
- 使う期間:1組のバックテストと完全に一致すること。清算の式と、次の区切りの初期資金
- つなぎ方:区切りが1つなら、つないだ成績は(最後の清算を除いて)その使う期間の1組のバックテストと一致すること
- API の結果が、リファレンス実装(`engine/reference/walkforward.py`)を順番に計算した結果と一致すること
- 入力チェックの文:設定・区切りが作れない・計算が多すぎる、の表(`tests/fixtures/walkforward_messages.json` を API と画面の両方のテストが読む)
- 画面〜API〜計算:通しのテスト(`frontend/e2e/backtest.spec.ts`)で、DEMO:1003 の既定の条件の結果とアクセシビリティを確かめる

## 12. 既知の限界

- 区切りごとに清算するので、実際より売りの費用を多めに引く(5章)
- 区切りごとに株を持たない状態から始め、次のゴールデンクロスまで買わない(5章)。前の区切りの持ち株や「短期線が上にある」状態を引き継ぐ方法
  (同じ日数を選んだら持ち続ける、区切りの初日に短期線が上なら買う、など)は、まだ決めていない。決めるときは、1組のバックテスト(`docs/mvp.md`)とは別の決まりになる
- 選ぶ期間の長さ・使う期間の長さ・基準そのものを選ぶ方法はない。いくつも試して良いものを選ぶと、それも過剰最適化になる
- 選ぶ期間は「直近 I か月」だけ(過去を全部使う方法:アンカード、はない)
- 1銘柄だけ
