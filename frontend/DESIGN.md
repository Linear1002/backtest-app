# 画面のデザインの決まりごと

誰が・何のために使う画面か:**個人投資家が、売買ルールを過去の株価で確かめる**ための日本語の道具。
数字を正直に見せること(手数料を引いた損益、清算コスト控除前、生存者バイアスの注意)を、見た目より優先する。

## 色

| 名前 | ライト | ダーク | 使う場所 |
|---|---|---|---|
| 紙(paper) | `#f3f5f2` | `#0f1217` | 画面の背景 |
| 面(surface) | `#ffffff` | `#171b22` | パネル・チャートの背景 |
| 墨(ink) | `#1d2330` | `#e6e9ee` | 本文・主要な数字・主ボタン |
| 墨2 / 墨3 | `#4a5362` / `#636c7a` | `#b5bdc9` / `#8d97a6` | 補足・ラベル(墨3 でも紙に対して 4.5:1 以上) |
| 罫(rule) | `#dfe5ea` | `#2a313c` | 罫線・目盛り線(帳簿の淡い青灰の罫) |
| 罫・強(rule-strong) | `#b8c4ce` | `#3d4653` | 表の見出しの罫、チップ・副ボタンの輪郭(文字があるので境界線の基準の対象外) |
| 入力欄の枠(field) | `#838e9a` | `#646e7d` | 入力欄の枠。紙・面のどちらに対しても 3:1 以上(WCAG 2.1 の 1.4.11。入力欄は枠でしか位置が分からないため) |
| 朱(shu) | `#c23b2e` | `#de6457` | **上昇・利益・買い**。エラー表示 |
| 藍(ai) | `#2c5aa0` | `#5f8dd8` | **下落・損失・売り**。ドローダウン |
| 短期線 | `#a8650b` | `#c0832f` | 短期移動平均 |
| 長期線 | `#0f8b74` | `#24a084` | 長期移動平均 |
| ヒートマップの中間(heat-mid) | `#e3e7e3` | `#2e343e` | ヒートマップの 0 の色(朱・藍のどちらでもない、色みのないグレー) |

- 値動きの色は**日本の習慣どおり**(上昇=朱、下落=藍)。証券会社の注文画面の「買い=赤、売り=青」とも合う
- 色だけで意味を伝えない。損益には必ず符号(+/−)を付け、約定には「買」「売」の文字がある
- 移動平均の2色は、色覚の多様性に配慮した検証(OKLab での差、背景とのコントラスト)を通した組み合わせ。朱・藍とも区別できる

## 文字

- 本文・数字:**BIZ UDPゴシック**(モリサワのユニバーサルデザインフォント。数字の読み間違いが起きにくい)。`@fontsource/biz-udpgothic`
- 印の文字だけ:**BIZ UDP明朝**の太字(`public/fonts/seal/` に「買・売・検」を含むファイルだけを置いている)
- 表や軸など、数字が縦にそろう必要がある場所だけ `.tabular`(等幅数字)。大きな単独の数字は比例幅のまま
- 見出しだけ `palt`(プロポーショナル字詰め)

## 「印」(判子)

このアプリでいちばん目立たせる要素。

- 約定は、朱の「買」・藍の「売」の印でチャートと取引の記録に押す(買いは約定価格の少し下、売りは少し上)
- アプリの印は「検」(検印=確かめた印)。ヘッダーと「バックテストを実行」ボタンにだけ使う
- 結果が出たときだけ、資産額の線を描き、印を押す動きを一度だけ入れる(`prefers-reduced-motion` のときは動かさない)

ほかの部分は静かにする:影はつけない、角丸は小さく、区切りは罫線で。

## 帳簿の作法

- 合計(最終資産、決済した取引の損益の合計)の下だけ、朱の二重線(締め線)を引く
- 表の数字は右寄せ、日付は左寄せ
- 注意書きは「※」で始める

## チャート

- 横軸は営業日の番号(休場日のすき間を詰める)。株価・資産額・ドローダウンの3段で横軸を共有し、十字線も共有する
- 分割・併合の権利落ち日は、株価と移動平均の線を切り、縦線と注記を入れる(値動きではないため)
- マウスでも、矢印キーでも日付を動かせる。数値はいつでも上の読み取り欄と「表で見る」で読める
- 目盛り線は1pxの実線(点線にしない)
- 比較の基準(買い持ち。`docs/benchmark.md`)の資産額は、墨3の**点線**で描く。売買ルールの資産額(墨の実線)と、色だけでなく線の形でも見分けられるようにする。凡例と読み取り欄にも同じ点線の印を付ける
- 比較の基準の値は、売買ルールの値の下に小さく・墨3で書く(主役は売買ルールの値)

## ヒートマップ(総当たり)

- 横=長期の日数、縦=短期の日数。1マスが1つの組み合わせ。短期 ≥ 長期のマスは計算しないので塗らない(読み上げでは「計算しない組み合わせ」と読む)。
  値が出せない組み合わせ(取引がなくシャープレシオが出ない、など)は「−」を書いて、0 の色と区別する
- 色は**値の向きで2種類**:シャープレシオ・総リターンは 0 を中心に、プラスは朱・マイナスは藍(中間は heat-mid のグレー)。
  最大ドローダウンは「小さいほどよい」の1方向なので、藍の濃さだけで表す
- 色は CSS の `color-mix(in oklab, …)` で、朱・藍と heat-mid を混ぜて作る。ダークモードも同じ式(heat-mid だけ暗い色に替える)。
  0 から離れるほど明るさが一方向に変わる(ライトでは暗く、ダークでは明るく)ことを OKLab の明るさで確かめてある(色の見分けにくい人にも、強さの順番は読める)
- **色の物差しは選ぶ期間の値だけで決め、検証期間も同じ物差しで塗る**(切り替えても、同じ色が同じ値を表す)。検証期間の値で物差しを決めると、
  選ぶ画面の色の濃さに検証期間の情報が入り込むため。物差しを超える検証期間の値は端の色にし、そのことを凡例の下に書く。
  弱い値でもグレーと見分けられるよう、色の濃さは少しだけ底上げする
- 選ぶ期間の1位は**太い枠**(墨の枠の内側に面の色の細い枠を重ねる。濃い朱・藍のマスの上でも、枠と周りの差を 3:1 以上に保つ)。
  同率1位のときは枠を付けない。色を変えない(色は値のためだけに使う)
- 選んだマスは**中央の黒い点**、キーボードのフォーカスは**外側の墨の線**。2つを見た目で区別する
- 長期の候補が多いときも、1マスの幅を一定以上に保ち、はみ出す分は横にスクロールする
- 数字を全部のマスには書かない。指したマス(マウス・キーボード)の値は上の読み取り欄に文字で出し、全部の値は「表で見る」で読める。
  色の差が小さいマスがあっても、数字はいつでも文字で読める
- キーボード:矢印キー・Home・End で動き、Enter・スペースで選ぶ(WAI-ARIA の grid。フォーカスのあるマスは1つだけ)
- 色の物差しには、買い持ちの値の位置に墨の縦線を引く(面の色で縁取る)。凡例に「物差しの縦線:買い持ち(値)」と文字でも書く

## 言葉づかい

- ボタンは押したら何が起きるかを書く(「この銘柄で進む」「バックテストを実行」)
- エラーは何が起きて、どう直せばよいかを書く。謝らない
- 中身が空のときは、次に何をすればよいかを書く(例:シグナルが出なかった → 期間を広げる)
