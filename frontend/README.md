# frontend

Next.js(TypeScript・Tailwind CSS・App Router)の画面。起動方法などはリポジトリ直下の `CLAUDE.md` の「コマンド」欄と `Makefile` を参照。

- 開発サーバー:リポジトリ直下で `make dev-api`(API)と `make dev-web`(画面)→ http://localhost:3000
- 画面からの `/api/...` は `next.config.ts` の rewrites で FastAPI(既定は http://localhost:8000、環境変数 `BACKEND_URL` で変更可)に転送する
- テスト:`npm test`(`lib/` の計算・表示の関数。Node.js の test runner で TypeScript をそのまま動かす)
- 通しのテスト:リポジトリ直下で `make e2e`(画面を本番ビルドし、Playwright で画面〜API〜エンジンを通して確かめる。架空データだけを使う。
  初めてのときは `npx playwright install --with-deps chromium` でブラウザを入れる。設定は `playwright.config.ts`)
- デザインの決まりごと:`DESIGN.md`
- `AGENTS.md` は `next dev` が自動で書き戻すファイルなので、消さずにコミットしておく

## ファイルの構成

| 場所 | 中身 |
|---|---|
| `app/` | レイアウト・トップページ・色や文字の設定(`globals.css`) |
| `components/BacktestApp.tsx` | 手順(銘柄 → 戦略 → 条件 → 確認 → 結果)の画面を並べ、API を呼ぶ |
| `lib/flow.ts` | 手順の状態と移り変わり(reducer)。古い応答を捨てる・条件を変えたら前の結果に戻れない、などの決まり。1組のバックテストと総当たりの両方 |
| `components/steps/` | 手順1〜4の画面(総当たりの確認・途中経過は `SweepConfirmStep.tsx`) |
| `components/results/` | 結果の画面(計算書・成績表・チャート・取引の記録・注意) |
| `components/sweep/` | 総当たりの結果の画面(`SweepView.tsx`:まとめ・上位の表・注記、`Heatmap.tsx`:ヒートマップ) |
| `lib/api.ts` | API の型と呼び出し |
| `lib/format.ts` | 円・%・日付の表示 |
| `lib/chart.ts` | チャートの目盛り・座標・線のパス |
| `lib/numbers.ts` | 入力欄の文字 → 数値(全角数字・カンマを受け付ける) |
| `lib/form.ts` | 条件の入力チェック(範囲は API の ParamSpec から読む。メッセージは docs/mvp.md 4.3・API と同じ) |
| `lib/sweep.ts` | 総当たりの組み合わせの数・入力チェック・検証期間の開始日・ヒートマップの色(docs/sweep.md。メッセージは API と同じ) |
| `lib/benchmark.ts` | 比較の基準(買い持ち。docs/benchmark.md)の見せ方:買えなかったときの説明、総リターンの差、良い・悪いの言い方 |
| `lib/sweepJob.ts` | 総当たりのジョブを始めて、終わるまで途中経過を問い合わせる(失敗したときのやり直し・中止の頼み方) |
| `lib/testing.ts` | テスト用の小さなデータ(アプリからは使わない)。パラメータの定義は API と共有する `tests/fixtures/` から読む |
| `e2e/` | 画面〜API〜エンジンを通すテスト(Playwright)。各手順でアクセシビリティの自動チェック(axe)もする |

## 状態の決まり(lib/flow.ts)

画面の状態は React の部品の中ではなく、`lib/flow.ts` の reducer(「いまの状態」と「起きたこと」から次の状態を返す純粋な関数)にまとめている。
画面を開かなくても `npm test` で確かめられるようにするため(`lib/flow.test.ts`)。

- **古い応答は捨てる**:銘柄の詳細・バックテストの実行には番号を付け、いちばん新しい番号の応答だけを受け取る(A を押してすぐ B を押したとき、遅れて届いた A の詳細で B の条件を上書きしない)
- **結果は、その結果を出した条件でだけ見られる**:条件を変えたら手順5には移れない(元の条件に戻せば、また見られる)
- **実行中は、手順の移動・条件の変更・銘柄の選び直しを受け付けない**(送ったリクエストと画面の条件をずらさないため)
- **API のエラーは、出せる場所に出す**:入力欄のエラー(期間・日数など)は条件の画面のその欄へ。それ以外は確認の画面に文で出す
- **手順が変わったら見出しへ、入力に誤りがあれば最初の誤りの欄へフォーカスを移す**(読み上げ・キーボード操作のため)
- **同じ銘柄を選び直しても何も消さない**。別の銘柄にしたら、日数・費用・初期資金は残し、期間だけを新しい銘柄のデータの範囲にする

### 総当たり(docs/sweep.md)

- 条件の画面の「1組で試す / 総当たりで比べる」で切り替える。1組の結果と総当たりの結果は別々に覚える(切り替えても消えない)
- 実行するとジョブの番号が返り、400ミリ秒ごとに途中経過を問い合わせる。**応答の番号が、いちばん新しい実行の番号と違えば捨てる**(1組のときと同じ)
- 問い合わせが失敗しても、待つ時間を倍にしながら3回までやり直す。それでもだめなとき・画面を閉じたときは、ジョブの中止を頼む(`lib/sweepJob.ts`)
- 「中止する」は API にジョブの中止を頼む。中止が済んだことは問い合わせの続きで受け取り、確認の画面に「中止しました」と出して、そこへフォーカスを移す。
  中止を頼めなかったときは、その場で知らせる。画面を閉じて問い合わせが来なくなったジョブは、API が60秒で打ち切る
- 読み上げは、途中経過の数字が変わるたびではなく、始め・4分の1・半分・4分の3の区切りだけ
- ヒートマップのマスを選んで「選ぶ期間で詳しく見る」「検証期間で詳しく見る」を押すと、**その期間だけ**の1組の条件になる(手順4で確認してから実行)。
  総当たりの表のその行と同じ計算なので、数字が一致する。確認の画面と結果の画面には、総当たりの中から選んだものだと書く。
  出どころは「詳しく見る」を押したときに記録し(`inspected`)、その条件のまま実行した結果にだけ引き継ぐ(自分で同じ条件を入れただけの結果には付けない)。
  エンジンかデータの取得日時が総当たりと違うときは、「同じ計算です」とは書かない
- 「総当たりの結果に戻る」(確認の画面・結果の画面)は、総当たりを実行したときの条件(エンジンも)に戻し、結果の画面の見方(並べる基準・色を付ける期間・選んだマス)もそのまま残す。
  「詳しく見る」から来た条件でないときは、押すと条件が置き換わることをボタンの下に書く

## 書き方の決まり

- 表など、横・縦にスクロールする枠は `components/ui.tsx` の `ScrollRegion` で包む。
  - キーボードだけでもスクロールできるよう、フォーカスを受け取り、名前を持つ(WCAG 2.1.1。axe の scrollable-region-focusable)
  - `relative` を付けてある。読み上げ用に隠した文字(`sr-only`)は `position: absolute` なので、枠に `relative` がないと枠の外に出て、
    スマートフォンでページ全体が横にはみ出す(E2E の「列の多い格子」のテストで、ページの横幅を確かめている)
  - 中にボタンなどフォーカスできるものがある枠(ヒートマップ)は、`relative` だけでよい
